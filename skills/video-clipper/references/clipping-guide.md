# 切片定位方法论

## 核心原则

切片质量 = 选段质量 × 去卡顿效果 × 音画同步

先记住一句：

> **后面的精切再强，也救不了前面选错的段。**

所以整个系统必须拆成：

- **选段器**：负责决定切什么
- **执行器**：负责把选好的段切好

并且选段器要同时支持两种模式：

- **观点版（opinion）**：讲清楚一个观点
- **金句版（punchline）**：一句话传播

两种模式都要过 **AI 验收 gate**，没过就不能进 `clips.list`。

### 观点完整性判断标准（opinion）

一条合格的**观点版**切片必须至少包含以下 4 项中的 3 项：

1. **引入**：观点的起因/背景（1-2 句）
2. **论述**：核心观点展开
3. **支撑**：例子、解释或展开
4. **落点**：结论、金句或听众反应

**常见错误：**

- ❌ 从金句开始切——缺少上下文，观众听不懂
- ❌ 观点讲到一半截断——最致命的错误
- ❌ 前面带了无关的过渡/闲聊——显得拖沓
- ❌ 后面带了下一个话题的开头——让观众困惑

### 金句成立性判断标准（punchline）

一条合格的**金句版**切片必须同时满足：

1. 单句本身成立
2. 不依赖大量前文背景
3. 传播感强，适合标题/钩子
4. 切完之后不会让人明显觉得“话只说了一半”

### 定位流程

```
insights 摘要 / transcript
     ↓
先决定模式（opinion / punchline）
     ↓
生成候选时间段
     ↓
AI 验收 gate（通过 / 打回 / 改模式）
     ↓
通过后写入 clips.list
     ↓
执行器切片 + 精切 + 字幕 + 质检
```

### AI 验收 gate

对每个候选片段，AI 至少要回答：

1. 这段脱离原视频上下文，能不能独立成立？
2. 开头 3-5 秒是否能听懂主题？
3. 是否有明确观点，而不只是情绪或口号？
4. 是否有支撑（解释/例子）？
5. 结尾是否收住？
6. 它更适合 `opinion`、`punchline`，还是应该 `reject`？

推荐输出结构：

```json
{
  "mode": "punchline",
  "decision": "pass",
  "start": "00:10:26",
  "end": "00:10:49",
  "title": "龙虾热的三拨人",
  "why_selected": "开场定义清晰，传播感强",
  "why_passed": ["单句成立", "不依赖太多上下文"],
  "risks": ["更适合金句片，不适合观点片"]
}
```

### 扩展确认

首次定位后，**必须**向前后各扩 2-3 分钟查看文字：

- 向前扩展：确认没有重要的铺垫被漏掉
- 向后扩展：确认观点确实讲完了，不是在下一段才有结论

## 去卡顿技术方案对比

| 方案                  | 音画同步      | 速度 | 质量             |
| --------------------- | ------------- | ---- | ---------------- |
| `select/aselect` 滤镜 | ❌ 会漂移     | 快   | 差               |
| `silenceremove` 滤镜  | ❌ 只处理音频 | 快   | 差               |
| 提速 1.05-1.1x        | ✅            | 最快 | 一般（改变语速） |
| **segment + concat**  | ✅            | 慢   | **最好**         |

### 为什么 segment+concat 最靠谱

`select` 滤镜的问题：音频采样率和视频帧率的时间基不同。当你用 `between(t,...)` 跳过一段时间时，音频跳过的实际时长和视频跳过的不完全一致。跳过的段越多，累积漂移越大。一条 2 分钟的切片里跳 20 次，到结尾可能就差了 0.5-1 秒。

segment+concat 的原理：每段都是从原始文件里独立切出来的完整片段，音视频保持原始对齐关系。拼接时 ffmpeg 的 concat demuxer 按顺序拼接，每段内部不做任何时间基转换。

### 静音检测参数

- **阈值 -30dB**：适合大多数直播/会议场景。太低（如 -40dB）会漏检，太高（如 -20dB）会把轻声说话也当成静音
- **最短 0.5s**：人说话的自然停顿通常 0.1-0.3s，0.5s 以上才是"卡顿"
- **嘈杂环境**：如果背景噪音大，调高到 -25dB
- **录音棚环境**：可以降到 -35dB，连更细微的停顿都去掉

## 平台适配建议

| 平台   | 推荐时长 | 比例         | 备注                 |
| ------ | -------- | ------------ | -------------------- |
| 抖音   | 30s-3min | 9:16 竖屏    | 前 3 秒必须有钩子    |
| 视频号 | 1-5min   | 9:16 或 16:9 | 偏正式内容可以长一些 |
| 小红书 | 30s-2min | 3:4 或 9:16  | 封面图很重要         |
| B站    | 2-10min  | 16:9         | 可以更完整           |
| 知乎   | 1-5min   | 不限         | 配合文字回答效果好   |

## 后处理建议

切片输出后通常还需要：

1. **加字幕**：用剪映/CapCut 自动识别 + 手动校对
2. **加封面**：提取金句做封面图
3. **加片头/片尾**：品牌标识
4. **竖屏适配**：如果原始是横屏 16:9，需要裁切或加背景模糊
