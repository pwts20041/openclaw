# X 每日推文管线（V3：社交驱动 + 图片必备）

> **一周验证期（2026-03-11 ~ 03-17）**
> 目标：单条平均浏览从 30 拉到 200+，有赞有转发。
> 做不到就砍掉这条管线。

三个阶段：

1. **回复**（`task=reply`）— 蹭热帖曝光，每天 3-5 条
2. **生成**（`task=generate`）— 原创帖，每天最多 2 条
3. **发布**（`task=publish`）— 发原创帖

---

## 触发条件

- cron 触发（传入 `task=reply`、`task=generate` 或 `task=publish`）
- 用户手动说"发X""回复热帖""生成推文"

---

## 核心策略变更（V2 → V3）

### 数据驱动的教训（2026-03-03 ~ 03-10）

| 指标         | V2 期间实际值 | V3 目标                   |
| ------------ | ------------- | ------------------------- |
| 每日发帖量   | 5-6 条        | **2 条原创 + 3-5 条回复** |
| 单条平均浏览 | 14-40         | **200+**                  |
| 赞/转发      | 0             | **>0**                    |
| 带图比例     | 0%            | **100%**                  |

### V3 三个核心改变

1. **砍量加图**：从 5-6 条纯文字砍到 2 条，每条必须带图
2. **社交优先**：每天先回复 3-5 条热帖（蹭曝光），再发原创
3. **数据闭环**：每周一拉数据复盘，不凭感觉

## 阶段零：回复热帖（task=reply）

这是涨曝光最快的方式。216 粉丝的账号，自说自话没人看。

### 1) 找热帖

用 browser 打开搜索页：

- `x.com/search?q=AI%20agent%20OR%20vibe%20coding%20OR%20Claude%20Code%20OR%20OpenClaw&f=top`
- `x.com/search?q=独立开发%20OR%20超级个体%20OR%20AIGC&f=top`

筛选标准：

- 浏览 > 5000 或 赞 > 50
- 24 小时内发的
- 话题和咱们账号相关

选 3-5 条。

### 2) 写回复

每条回复要求：

- **有增量信息**（不是"赞同""说得好"）
- **带自己的经验/数据**（"我试过，结果是…"）
- **短**（2-4 行，不要写小作文）
- **可以适度有态度**（"我不同意这一点，因为…"）

禁止：

- 纯吹捧
- 硬广（不要提 OpenClaw / ai-shifu 除非话题直接相关）
- AI 味句式（同下方禁用表达）

### 3) 发布回复

```
browser start (profile=openclaw)
导航到目标帖子
点击回复框
注入回复文本
点击回复按钮
确认发送
```

### 4) 记录

每条回复记录到 `x-posts/回复log.md`：

```
## 2026-03-11
- 回复了 @xxx 的帖子（浏览 12k）：[回复内容摘要]
- 回复了 @yyy 的帖子（浏览 8k）：[回复内容摘要]
```

## 阶段一：生成推文（task=generate）

### 1) 素材收集

按优先级：

1. `memory/` 今天与昨天日志
2. 当天关键操作（部署、修复、发布、复盘）
3. 已有博客草稿/文章

提取候选点，每条需要：

- 事件（发生了什么）
- 冲突（哪里翻车/反常识）
- 证据（数字/报错/时长/金额）
- 观点（一句话）

### 2) 选题打分

10 分制：

- 冲突强度（0~3）
- 可证据化（0~3）
- 与账号定位相关（0~2）
- 可转述性（0~2）

**只保留 ≥ 7 分的。最多选 2 条。**（不是 4 条，不是 5 条）

### 3) 写作格式（硬约束）

1. **第一行=钩子**（10~22字，单独成行）
2. 全文 3~8 行，短句
3. **至少 1 个硬证据**（数字、错误码、时间、金额）
4. **明确态度句**
5. 结尾：观点收口 或 互动问句
6. 字数上限：280 字

### 4) 图片生成（必须！无图不发！）

每条推文必须配一张图。优先级：

1. **终端/代码截图**（最真实）— 用 PIL 或 browser 截图
2. **数据对比图**（表格/柱状图）— 用 PIL 画
3. **架构图/流程图**（简洁的框图）— 用 PIL 画
4. **金句卡片**（纯文字排版）— 用 PIL 画，大字 + 简洁背景

生成方式：

```python
# 用 PIL 生成图片，存到 x-posts/images/
from PIL import Image, ImageDraw, ImageFont
# ... 根据内容类型生成
# 保存到 /Users/geyunfei/dev/openclaw/workspace/x-posts/images/{DATE}-{N}.png
```

图片尺寸：1200x675（X 推荐 16:9）

**无图的推文直接废弃，不入待发池。**

### 5) 推荐结构模板（五选一）

#### 模板1：翻车反转

- 钩子（翻车）
- 过程（做了什么）
- 证据（报错/数据）
- 反转结论

#### 模板2：反常识结论

- 钩子（打脸常识）
- 证据（个人案例 + 数字）
- 结论一句话

#### 模板3：实战清单

- 钩子（场景）
- 3 条动作
- 结果数据

#### 模板4：对话切片

- 一句对话（钩子）
- 冲突
- 顿悟句

#### 模板5：立场辩论

- 争议观点
- 证据
- 立场锁定

### 6) 质量门禁

- [ ] 第一行能独立当标题
- [ ] 有具体证据（不是"很多/不少"）
- [ ] 有明确立场
- [ ] 删掉最后一句信息仍完整
- [ ] 读起来像人说话
- [ ] **有配图**

### 7) 去 AI 味检查

**违禁句式（出现即重写）：**

- 在这个时代 / 值得一提 / 某种意义上 / 不得不说
- 不是A而是B / 与其A不如B
- 这不仅是A，更是B
- 由此可见 / 综上所述 / 给我们很多启发
- 然而 / 因此 / 此外 / 首先其次最后
- 深度赋能 / 价值闭环 / 全面提升 / 持续优化

**语感检查：** 朗读一遍，像微信语音才过；像汇报材料就重写。

### 8) 产物落盘

存到：`x-posts/待发/{DATE}-{N}.md`

每条附注释 + 图片路径：

```markdown
<!-- angle: 翻车反转 | score: 8 | image: x-posts/images/2026-03-11-1.png -->

正文...
```

图片存到：`x-posts/images/{DATE}-{N}.png`

**每天最多 2 条入待发池。**

## 阶段二：发布推文（task=publish）

### 1) 读取待发

```bash
ls x-posts/待发/*.md
```

无文件就汇报"无待发推文"。

### 2) 发布到 X

```
步骤 1: browser start (profile=openclaw)
步骤 2: navigate -> x.com/compose/post
步骤 3: snapshot 找 textbox
步骤 4: click textbox
步骤 5: 注入文本（ClipboardEvent paste）
步骤 6: 上传图片（点击图片按钮，用 upload 或 CDP 注入文件）
步骤 7: snapshot 确认文本+图片都在
步骤 8: click 发帖
步骤 9: snapshot 确认成功
步骤 10: browser stop
```

### 文本注入代码

```javascript
() => {
  const el = document.querySelector('[contenteditable="true"][role="textbox"]');
  if (!el) return "not found";
  el.focus();
  const text = "替换为推文内容";
  const dt = new DataTransfer();
  dt.setData("text/plain", text);
  const pe = new ClipboardEvent("paste", { clipboardData: dt, bubbles: true, cancelable: true });
  el.dispatchEvent(pe);
  return "pasted";
};
```

### 图片上传

找到图片上传按钮（通常是 `input[type="file"]` 或媒体按钮），用 browser upload 功能上传对应的图片文件。

### 3) 归档

```bash
mv x-posts/待发/XXX.md x-posts/已发/
```

### 4) 链式调度

发完后检查待发池：

- 还有 → 安排下一条（+30min ~ 今天 23:20 随机）
- 空了 → 不安排

用 `cron(action=add)` 创建 at 类型一次性任务：

- payload: `读 skills/x-daily/SKILL.md，执行 task=publish。`
- delivery: announce
- sessionTarget: isolated

## 阶段三：每周数据复盘（task=review）

每周一执行。

### 1) 拉数据

用 browser 打开 `x.com/geyunfei`，逐条记录过去 7 天帖子的：

- 浏览量
- 赞数
- 转发数
- 回复数
- 书签数

### 2) 分析

- 哪种模板/话题表现最好？
- 回复热帖带来了多少 profile 访问？
- 带图 vs 纯文字的差异？
- 与上周对比的变化

### 3) 输出

写入 `x-posts/weekly-review-{DATE}.md`，包含：

- 数据表格
- Top 3 帖子分析
- 下周策略调整建议
- 与目标（200+ 浏览）的差距
