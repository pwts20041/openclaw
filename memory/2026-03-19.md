# 2026-03-19

## Ada（openclaw-team 实例）故障排查与收敛

### 背景/目标
- 需求：把 Ada 先“拉起来”可用；后续再修模型/插件等问题。

### 关键现象（最初）
- openclaw-team 实例 gateway 未运行/未配置（openclaw.json 缺失）。
- 手工启动过程中出现 stale lock / “gateway already running (pid XXXX)”（pid 实际不存在）。
- 同步主实例配置后，出现大量报错：
  - OpenAI Codex OAuth refresh token 401（`refresh_token_reused`），导致模型调用 fallback。
  - boot-md 读取其他 workspace 的 `BOOT.md` 触发 EACCES。
  - `missing scope: operator.read`（Control UI/客户端连接后 status/config.get 等 RPC 被拒）。

### 采取的动作
1) **先拉起 gateway（openclaw-team）**
   - 固定 loopback 端口：`127.0.0.1:18790`（避免与主实例 18789 冲突）。
   - 期间曾用 `--allow-unconfigured` 方式应急启动。

2) **配置同步（后来证明不应把 agent 列表一并同步）**
   - 同步了主实例的 `~/.openclaw/openclaw.json` 和 `auth-profiles.json` 到 openclaw-team。
   - 结果导致 Ada 读取了不属于 openclaw-team 的 workspace/agent 列表，触发 boot-md EACCES。

3) **端口修正与配置收敛**
   - 将 openclaw-team 的 `gateway.port`/`bind` 修正为 `18790`/`loopback`。
   - 明确结论：**Ada 不应同步团队 agent 列表**。
   - 将 openclaw-team 配置收敛为 **只保留一个 agent（main）**，移除会触发跨-workspace 的 `boot-md` hook。

4) **飞书配置去冗余**
   - 按要求将 Ada 的 Feishu 配置收敛为只启动 `feishu[default]`，不再启动 fortune/jaoyan/project/writer/yunying 等 accounts。

5) **修复配置文件语法损坏（JSON5 parse failed）**
   - openclaw-team 的 `~/.openclaw/openclaw.json` 一度出现 JSON5 语法断裂（`invalid end of input`），导致 CLI/doctor 无法正常读 config。
   - 通过手工修补 `channels.feishu` 末尾多余逗号/花括号后恢复为可解析（PARSE_OK），并重启 gateway。

### 当前状态（收敛后）
- Ada gateway：`http://127.0.0.1:18790/` 探活 200；进程正常。
- Feishu：仅启动 `default` account。
- 仍可能出现的日志噪音：`missing scope: operator.read`（通常为 Control UI/客户端未携带 operator.read scope/token 导致的 status/config.get 被拒），不等同于服务宕机。

### 经验/规则
- 多实例同机：必须固定不同端口（主实例 18789，Ada 18790），避免冲突。
- **不要把团队 agent 列表同步给 Ada**；Ada 应保持单 agent + 自己 workspace。
- 如果看到 `missing scope: operator.read`，优先检查 Control UI/客户端是否用正确 token 登录并携带 operator scopes。

## Ada 飞书“能收不能回”根因补充（16:55 左右）
- Ada 并不是“收不到飞书消息”，日志明确显示 `feishu[default]` 能收到拐爷私聊，并成功 dispatch 到 agent。
- 真正故障点在**最终回复发送**阶段：日志报错 `feishu[default] final reply failed: Error: getaddrinfo ENOTFOUND open.feishu.cn`。
- 结论：当时是 **openclaw-team 用户环境/DNS 链路无法解析 `open.feishu.cn`**，导致 Feishu OpenAPI 发信失败；而 Feishu WebSocket 仍是连通的，所以表现为“能收消息但不回复”。
- 补充验证：
  - `open.larksuite.com` 可解析；
  - `open.feishu.cn` 在 openclaw-team 环境里解析失败；
  - `dig @8.8.8.8 open.feishu.cn` 能解析到 IP，说明更像是本机 DNS 分流/缓存/VPN 相关问题，不是 Feishu 服务整体宕机。
